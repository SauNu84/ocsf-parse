§1 · Data Architecture

End-to-end data flow — single pipeline, multi-tier storage

Dữ liệu đi qua 4 tier vật lý trên object storage (Bronze → Silver → Gold → Platinum). Mỗi tier là một Parquet dataset độc lập, có thể swap engine bên trên mà không cần re-ingest. Boundary giữa các tier là schema-on-write — không phải convention truyền miệng.

BRONZE — raw, as-is SILVER — OCSF normalised GOLD — Dim/Fact star PLATINUM — detect + ML

Architecture principles — 4 invariant rules

01

Storage = open format

Mọi tier là Parquet trên object storage (S3 / GCS / Azure Blob). Không proprietary binary. Engine query có thể swap (Trino / DuckDB / Spark / Snowflake / Athena) mà không re-load data.

02

Schema = OCSF, versioned

Silver tier chỉ chấp nhận record valid với OCSF v1.8. Mapping JSON là code, peer-reviewed, CI-linted. Schema drift bắt ngay ở write, không phải ở query.

03

Partitioning = predictable

Hive-style class_uid=NNNN/event_day=YYYY-MM-DD/. Mọi query lọc theo class hoặc ngày prune được ở directory level — không scan partition không liên quan.

04

Lineage = automatic

Mỗi record giữ metadata.uid (raw line hash) + metadata.product (source). Truy ngược từ alert → fact_event → silver event → bronze raw line trong 1 query.

§2 · OCSF — The canonical schema

Vì sao chọn OCSF làm "lingua franca" của security data

OCSF (Open Cybersecurity Schema Framework) là canonical schema cho security telemetry, sponsor bởi CISA · AWS · Splunk · IBM · CrowdStrike · Cloudflare · Salesforce. Vendor-agnostic, version-controlled, open-source. Đây là cái thay thế "JSON tự do" bằng "JSON có hợp đồng".

OCSF là gì — structurally

3 cấp phân loại + 1 type system:

  • Category — 8 nhóm cao nhất (System / Findings / IAM / Network / Discovery / App / Remediation / Unmanned)
  • Class — ~80 event class (Process Activity, Authentication, DNS Activity, Detection Finding...)
  • Object — ~120 reusable nested type (User, Endpoint, Process, File, Network Connection...)
  • Dictionary — single source of attribute names, types, enum values

Mỗi event có class_uid (số định danh) + activity_id (loại hoạt động trong class) + các trường đã chuẩn hoá.

Cụ thể: 1 dòng nginx access log → 1 OCSF HTTP Activity event

Bên trái là raw line. Bên phải là OCSF event sau khi ocsf-parse apply mapping. Mọi field tên giống nhau với event đến từ Cloudflare, F5, hay Envoy.

Vì sao OCSF (không phải ECS, CIM, hay schema tự build)

01

Vendor-neutral governance

Sponsor không phải 1 hãng — đây là điểm khác biệt với Elastic ECS (Elastic-led) hoặc Splunk CIM (Splunk-led). Schema do steering committee đa hãng quyết.

02

Versioned + backward-compatible

v1.0 → v1.8 → v1.9-dev. Mỗi version pinned trong git submodule. Lint gate phát hiện breaking change trước khi merge mapping.

03

Drop-in cho AWS Security Lake

Security Lake ăn đúng layout này (OCSF + Parquet + Hive partition). Đầu tư vào pipeline = đầu tư vào managed service path nếu sau này cần.

04

Có ecosystem

Splunk OCSF add-on · CrowdStrike OCSF export · Microsoft Sentinel OCSF connector · AWS Glue schema registry — tất cả speak OCSF natively.

Tại sao star schema chứ không phải One Big Table

01

Analyst nói cùng ngôn ngữ

Tableau / Looker / Superset / Power BI hiểu native star schema. Drag-drop join, không cần SQL phức tạp. CTE-heavy query thành click.

02

Storage gọn 10–30×

Mỗi user lưu 1 lần ở dim_user, không phải nhắc lại trong 1 triệu fact row. Compression ratio tốt hơn nhiều so với denormalised.

03

Slowly-changing tự nhiên

SCD-2 trên dim_endpoint giữ lịch sử IP reassign. Forensic query "ai sở hữu IP X tháng 3" trả lời được, không bị overwrite.

04

Feature pipeline reuse

DS xây feature từ fact_event JOIN dim_* — cùng dataset analyst đang dùng. Một source of truth, không lệch giữa report và model.

§4 · Data Serving

4 pattern serving — mỗi consumer dùng layer phù hợp

Không phải mọi consumer cần cùng latency, cùng granularity, hay cùng tool. Kiến trúc tách 4 serving pattern, mỗi pattern có SLA và technology stack riêng, nhưng tất cả đọc từ cùng Parquet trên S3.

SOC ANALYST

Interactive SQL + ranked queue

Triage alert · investigate incident · hunt

freshness: T + 60s (Silver) / T + 15min (Gold)

Đọc alert_scored sort theo ml_score DESC. Drill-down qua fact_event JOIN dim_user. Pivot timeline qua silver/ocsf.

stack: DuckDB · Trino · Athena

DATA ANALYST · EXEC

BI dashboards + reports

KPI · trend · compliance reporting

freshness: T + 1h (Gold refresh)

Tableau / Looker / Superset point straight vào Gold star. Pre-aggregated cube cho hourly/daily/weekly views. Sub-second dashboard load.

stack: Tableau · Superset · Looker · Power BI

DATA SCIENTIST

Feature pipeline + notebook

Feature eng · model train · backtest

freshness: T + 24h (daily features)

Đọc Parquet trực tiếp bằng pandas / Spark / DuckDB. Feature store dựng từ fact_event. Re-train RF hàng tháng. Disposition feedback loop closing the loop.

stack: pandas · sklearn · Spark MLlib · MLflow

DOWNSTREAM SYSTEMS

Programmatic API + streaming

SOAR · ticketing · enrichment

freshness: T + 5min (Tier-1 streaming)

REST endpoint trên Gold (GET /alerts?since=…&min_score=…). Webhook → SOAR khi disposition=pending. Kafka topic cho streaming consumers.

stack: FastAPI · Kafka · Webhook · SOAR connector

Example query — cross-source authentication failures (Silver tier)

-- Find users với failed auth từ ≥3 sources khác nhau trong 24h
-- Joins Okta + AD + Vault + SSH — works because OCSF normalises actor.user.name
SELECT
  actor.user.name              AS user_name,
  count(DISTINCT metadata.product.name) AS n_sources,
  count(*)                     AS n_failures
FROM   silver.ocsf
WHERE  class_uid   = 3002             -- Authentication
  AND  status_id   = 2                -- Failure
  AND  event_day   >= current_date - 1
GROUP BY actor.user.name
HAVING count(DISTINCT metadata.product.name) >= 3
ORDER BY n_failures DESC;

Example query — top risk users (Gold star)

-- BI dashboard query — sub-second vì pre-aggregated trên Gold
SELECT
  u.user_name,
  u.department,
  a.rule_id,
  a.ml_score,
  a.mitre_techniques
FROM   gold.alert_scored a
JOIN   gold.dim_user u USING (user_sk)
WHERE  a.event_day >= current_date - 7
  AND  a.ml_score  >= 0.6
ORDER BY a.ml_score DESC
LIMIT  20;

5.2 · Feature engineering — fact_event → user-day matrix

Đầu vào: gold.fact_event JOIN dim_user. Output: 1 row / user / day với 15 feature. Tổng 1,561 user-days từ 30 ngày data.

-- Feature pipeline (Phase A pre-aggregation — chạy 1 lần / ngày)
SELECT
  user_sk,
  event_day,
  count(*)                                              AS total_events,
  count(DISTINCT endpoint_sk)                          AS distinct_ips,
  count(DISTINCT class_sk)                             AS distinct_classes,
  count(DISTINCT region)                               AS distinct_regions,
  sum(CASE WHEN status_id = 2  THEN 1 END)             AS failed_auth,
  avg(CASE WHEN status_id = 2  THEN 1::float ELSE 0 END) AS failed_auth_rate,
  sum(CASE WHEN hour(event_ts) NOT BETWEEN 7 AND 19 THEN 1 END) AS off_hours_events,
  sum(CASE WHEN is_known_bad_ip      THEN 1 END) AS known_bad_ip_events,
  sum(CASE WHEN severity >= 4        THEN 1 END) AS high_sev_events,
  sum(CASE WHEN is_sensitive_op       THEN 1 END) AS sensitive_ops,
  -- 3 features khuyến nghị từ CISO review:
  mode(src_ip)                  AS single_ip_failed_ratio,        -- failures tập trung 1 IP
  mode(metadata.product.name)   AS single_product_failed_ratio,   -- failures tập trung 1 product
  zscore(hour, user_baseline)   AS hour_zscore_vs_baseline        -- giờ bất thường so với user
FROM   gold.fact_event
WHERE  event_day >= current_date - 30
GROUP BY user_sk, event_day;

5.3 · 2 model chạy song song — defense in depth

UNSUPERVISED

IsolationForest

sklearn · contamination=0.05 · 100 trees

Cold start
Chạy được ngày đầu — không cần labeled data, không cần training history.
Mục đích
Bắt outlier — user-day có hành vi khác lạ so với baseline tập thể.
Output
Anomaly score [-1, 1]. Threshold = top 5% xếp vào "unusual queue".
Điểm yếu
Không biết outlier là attack hay là exec đi công tác — analyst phải triage.
SUPERVISED

RandomForestClassifier

sklearn · 200 trees · class_weight=balanced

Cần
Labeled incidents từ SOC disposition (TP/FP/benign).
Mục đích
Học pattern attack đã biết → rank user-day theo P(incident).
Output
Calibrated probability [0, 1]. Top-K hợp với SOC capacity (e.g. 20/day).
Metric
PR-AUC (không phải accuracy) vì base rate cực thấp (~0.4% incident).

5.8 · Honest limitations — gì sampling/synthetic làm chúng ta miss

Production blockers — cần đóng trước khi go-live

  • Carol's brute force missed (#947). 10% sampling trên class 3002 (auth) drop 200-event burst. Fix: full-fidelity scan trên auth class, hoặc stratified sampling theo IP reputation, hoặc rolling-window feature max_failures_in_any_5min_window.
  • CEO trong MFA cluster proba thấp (0.147). Cùng pattern với 4 user kia nhưng ML đánh thấp — có thể do CEO có nhiều legit cross-region/off-hours activity làm baseline noise cao. Fix: per-role baseline thay vì global.
  • Vault rule 0 alert. Là bug synthetic data generator (không set status_id=2 cho denied events), không phải rule sai. Production data sẽ có.
  • Multi-region API 11,596 alert. Quá noisy cho prod. Cần allowlist của service identity hợp lệ cross-region (ETL job, monitoring agent, etc.).
  • MITRE coverage = 1 technique. Synthetic template không carry ATT&CK annotation. Real feed (CrowdStrike, Defender, Sentinel) sẽ surface 50–100 technique trên cùng volume.
  • Severity inflation ở 6 mapping. 100% events ở class Kernel/Vuln/Detection tagged High+ vì synthetic default. Cần calibrate mapping → 37 finding đã handoff cho mapping team.
